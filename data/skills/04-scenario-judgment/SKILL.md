# 场景判断

肺癌医生Agent应用层的第四个执行步骤。负责根据当前就诊的患者资料特征，判断所属的6种就诊场景类型，为后续问诊流程提供流程方向指引。

## 执行流程

### 1、标准的输入

（1）03-循环次数确定的输出（当前循环信息：当前就诊时间、既往就诊历史）
（2）当前就诊时间下的资料MD文件路径列表
（3）患者信息（年龄、性别、既往病史、家族史等）
（4）患者资料特征摘要（症状描述、已有检查报告类型、既往治疗记录）
（5）可选：RAG知识库路径 `skills/folder-rag/database/chroma_db`（边界场景时查询）

### 2、步骤说明

#### 步骤1：提取当前就诊资料特征

- 读取当前就诊时间下的所有资料MD文件
- 提取关键特征标识：
  - 是否包含症状描述（咳嗽、胸痛、咯血、气短等）
  - 已有检查报告类型（影像检查、病理检查、检验检查）
  - 是否有明确的影像学发现（结节大小、占位征象等）
  - 是否包含体检信息
  - 是否有既往治疗记录（手术、化疗、放疗、靶向、免疫等）
  - 是否有外院转诊资料

#### 步骤2：调用场景匹配子Skill

创建子Agent（`sessions_spawn`，`context="isolated"`）调用子Skill `skills/scenario-matching/SKILL.md`：
- 将提取的特征标识输入场景匹配逻辑
- 匹配6种场景之一
- 输出场景类型和判断依据

#### 步骤3：验证场景判断结果（含RAG辅助）

- 确认场景类型与当前就诊资料特征一致
- 如有冲突或边界模糊情况，进入RAG辅助分支：
  - 调用 `../_shared/knowledge-retrieval/SKILL.md` 查询相关临床场景知识
  - 查询内容：根据患者特征构建，如 `"肺结节 早筛 临床分类标准"`
  - 或 `"肺癌 转诊 判断标准 外院已检查"`
  - 使用检索结果辅助判断场景边界
  - 标记为"边界场景"，输出多个可能的场景选项供医生选择
- 如无冲突，直接确认场景判断结果
- 记录场景判断的推理过程（含RAG引用来源）

### 3、条件判断

#### 6种场景定义

| 场景编号 | 场景名称 | 特征条件 |
|----------|----------|----------|
| 场景1 | 未检查初诊 | 只有症状描述，没有影像、病理、检验等任何检查报告 |
| 场景2 | 检查后初诊 | 有症状描述 + 已完成一些必要检查（影像/病理/检验中至少一类） |
| 场景3 | 早筛怀疑初诊 | 症状不明显或无症状，有影像学提示（如体检发现的肺结节）和/或体检信息 |
| 场景4 | 转诊 | 从外院转入，已完成一些必要检查，自带外院检查报告和/或治疗记录 |
| 场景5 | 治疗后未检查 | 有既往检查记录 + 既往干预记录（手术/化疗/放疗/靶向/免疫等），本次无新检查 |
| 场景6 | 治疗后检查复诊 | 有既往检查记录 + 既往干预记录 + 本次已完成新检查 |

#### 判断优先级

1. 优先判断是否有外院转诊标记 → 场景4
2. 其次判断是否有既往治疗记录 → 场景5或6（取决于有无新检查）
3. 再判断是否有症状+检查 → 场景2或3（取决于体检/早筛特征）
4. 最后判断是否只有症状 → 场景1

### 4、错误处理

| 错误类型 | 处理方案 |
|----------|----------|
| 当前就诊无任何资料 | 按"只有症状"处理为场景1 |
| 场景特征同时满足多个场景 | 按优先级规则选择最匹配的场景，标记"边界场景"，启用RAG辅助 |
| 资料不完整无法判断 | 标记为"场景待定"，提示医生手动选择 |
| MD文件读取失败 | 尝试读取备选路径或提示用户补充 |
| RAG查询失败 | 降级为仅使用规则匹配，不引用 |

## 规则

### 1、被禁止的行为

（1）禁止在没有资料特征分析的情况下随机选择场景
（2）禁止将转诊患者判定为非转诊场景（场景4优先）
（3）禁止在特征不明确时主观推断场景

### 2、约束条件

（1）场景判断必须有明确的特征依据
（2）必须按优先级规则处理场景冲突
（3）边界模糊时必须标记"边界场景"标识
（4）转诊特征（外院资料、转诊单）优先级最高

### 3、鼓励的行为

（1）在判断依据中详细记录关键特征来源
（2）对边界场景启用RAG辅助查询，提供多个可能的场景选项供医生选择
（3）建立场景判断的置信度评分
