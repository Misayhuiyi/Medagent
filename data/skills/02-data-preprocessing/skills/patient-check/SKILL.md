# 患者检查

肺癌医生Agent资料预处理流程的第一步。负责根据患者姓名和门诊号查询患者—AI医生对应关系表，判断患者是否曾使用过AI医生服务。

## 执行流程

### 1、标准的输入

（1）患者基本信息：姓名、门诊号
（2）可选：患者—AI医生对应关系表路径（默认路径：`本地患者库/患者-AI医生对应关系表.json`）
（3）患者医疗文件路径（用于姓名交叉验证，如果有入院记录则从文件中提取真实姓名）

### 2、步骤说明

#### 步骤1：加载对应关系表

- 检查对应关系表文件是否存在（默认路径：`本地患者库/患者-AI医生对应关系表.json`）
- 如果文件存在，加载并解析JSON内容
- 如果文件不存在，返回「新患者（对应关系表不存在）」结果

#### 步骤2：姓名交叉验证

- ⚠️ **重要**：文件夹名/用户提供的姓名可能为化名或简称，必须以医疗文件（如入院记录）中的姓名为准
- 如果有入院记录MD文件，读取文件中姓名栏位（如"姓名：刘海平"），提取真实姓名
- 将真实姓名与提供的姓名对比，如果不一致，记录到对应关系表备注
- 后续所有操作以医疗文件中的真实姓名为准

#### 步骤3：查询对应关系表

- 在对应关系表中按门诊号匹配（优先）
- 如果找到匹配记录：返回「老患者」结果
- 如果未找到匹配记录：返回「新患者」结果

#### 步骤4：输出检查结果

- 输出JSON格式的检查结果（含验证后的真实姓名）

### 3、条件判断

| 条件 | 处理方式 |
|------|----------|
| 对应关系表不存在 | 返回「新患者」+ flag `tableMissing: true` |
| 按门诊号匹配成功 | 返回「老患者」+ 已有患者信息 |
| 按门诊号匹配失败但姓名匹配成功 | 进一步核对门诊号，不一致则标记为「需人工确认」 |
| 门诊号和姓名均不匹配 | 返回「新患者」|

### 4、错误处理

| 错误类型 | 处理方案 |
|----------|----------|
| 对应关系表JSON格式损坏 | 尝试修复或提示手动处理，返回「新患者」|
| 患者信息中包含特殊字符 | 使用URL编码或转义处理后在对应关系表中查询 |
| 查询超时或文件读取失败 | 返回「新患者」+ 错误信息 |

### 5、规范的输出

```json
{
  "isNewPatient": true/false,
  "patientId": "门诊号",
  "patientName": "姓名",
  "existingInfo": {
    "folderPath": "本地患者库/张三_001/",
    "visitDates": ["2026-01-15"],
    "historyCount": 2
  },
  "flags": {
    "tableMissing": false,
    "needsManualConfirm": false
  }
}
```

## 规则

### 1、被禁止的行为

（1）禁止在无对应关系表的情况下创建新患者记录时不初始化对应关系表
（2）禁止模糊匹配姓名导致张冠李戴

### 2、约束条件

（1）必须以门诊号为主要匹配依据
（2）对应关系表检查优先级：门诊号 > 姓名+门诊号
（3）对不确定的匹配结果标记为「需人工确认」，不可自行决定

### 3、鼓励的行为

（1）如果对应关系表存在但当前患者不在表中，检查是否存在同名患者提示用户确认
（2）记录每次查询操作到查询日志

## 工具声明（tools）
