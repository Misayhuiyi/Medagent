# 既往史

肺癌医生Agent患者病史总结流程的子Skill。负责从病历、出院记录、AI问诊记录中提取患者的既往病史信息，去重后按生理系统分类组织。

## 执行流程

### 1、标准的输入

（1）所有就诊时间的MD文件路径列表（重点：病历、医生诊疗文件夹）
（2）既往AI问诊输出记录路径列表（如有）

### 2、步骤说明

#### 步骤1：信息提取

- 从病历（入院记录）的「既往史」章节提取
- 从首次AI问诊记录中提取既往史
- 从出院记录中提取补充的既往史信息
- 记录每个信息的来源和提取时间

#### 步骤2：去重处理

- 相同疾病在不同来源中出现时，保留最早记录的版本
- 同样疾病的不同描述，合并为统一表述
- 时间冲突时，以病历记录为准

#### 步骤3：按系统分类

- 呼吸系统（COPD、哮喘、结核等）
- 心血管系统（高血压、冠心病、心衰等）
- 消化系统（肝炎、肝硬化、胃溃疡等）
- 内分泌系统（糖尿病、甲亢/甲减等）
- 泌尿系统（肾炎、肾功能不全等）
- 血液系统（贫血、凝血异常等）
- 神经系统（脑梗、帕金森等）
- 免疫系统（自身免疫性疾病等）
- 既往手术史（手术名称、日期）
- 既往外伤史

#### 步骤4：荟萃输出

- 每个疾病的信息：疾病名称、诊断时间、目前状态（已治愈/控制中/未控制）、治疗情况
- 输出结构化JSON

### 3、条件判断

| 条件 | 处理方式 |
|------|----------|
| 某系统无既往史 | 标记为「该系统无异常」|
| 既往史描述详细（多源）| 去重后保留完整版本 |
| 既往史仅提及病名无详情 | 记录病名，标记「详情不详」|

### 4、错误处理

| 错误类型 | 处理方案 |
|----------|----------|
| 病历无既往史章节 | 从全文智能提取相关描述 |
| 信息提取来源不存在 | 标记为「信息缺失」|
| 既往史描述模糊（如「多年前」）| 记录模糊时间，标记「时间不详」|

### 5、规范的输出

```json
{
  "summary": "患者既往有高血压病史7年...",
  "details": [
    {"system": "呼吸系统", "disease": "慢性支气管炎", "diagnosisTime": "2020年", "status": "已治愈", "treatment": "抗感染治疗", "source": "入院记录"},
    {"system": "心血管系统", "disease": "高血压", "diagnosisTime": "2018年", "status": "控制中", "treatment": "硝苯地平", "source": "入院记录"},
    {"system": "消化系统", "disease": "无异常", "notes": ""}
  ],
  "surgicalHistory": [
    {"surgery": "阑尾切除术", "date": "2010年", "hospital": "XX医院"}
  ],
  "traumaHistory": []
}
```

## 规则

### 1、被禁止的行为

（1）禁止将现病史内容混淆到既往史中
（2）禁止在无依据的情况下补充既往史

### 2、约束条件

（1）必须按生理系统分类输出
（2）必须记录每条信息的来源
（3）如某系统无异常也需标注「该系统无异常」

### 3、鼓励的行为

（1）注意区分「既往史」和「现病史」的时间边界
（2）关注与肺癌相关的既往疾病（如结核病史）
